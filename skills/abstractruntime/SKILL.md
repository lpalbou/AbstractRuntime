# AbstractRuntime

## Purpose and limits

Use Runtime to execute workflow graphs as persisted state machines with explicit
waits and an append-only ledger. A host supplies workflows, execution clients and
stores; Runtime is not a web server or a thin-client UI. In-memory stores are for
temporary runs. Use persistent stores and one writer process per file-store
folder when state must survive a restart.

## Install and verify

Install the version this skill describes (or newer):

```bash
python -m pip install "abstractruntime>=0.16.0"
```

The base profile includes remote-light AbstractCore integration and the MCP
worker. Choose `".[apple]"` or `".[gpu]"` only when this execution host needs
local inference engines. Verify the installed environment before doing work:

```python
from importlib.metadata import PackageNotFoundError, version
from inspect import signature
try:
    import abstractruntime
    installed = version("abstractruntime")
    assert callable(abstractruntime.Runtime), "Runtime API is unavailable"
    assert "display_text" in signature(abstractruntime.Runtime.steer).parameters, "Install AbstractRuntime 0.16.0 or newer for conversational guidance"
except (ImportError, PackageNotFoundError, AssertionError) as exc:
    raise SystemExit(f"Install verification failed: {exc}") from None
print(f"AbstractRuntime {installed}")
```

For inference, have the user configure credentials locally; never request keys
in chat. Give a remote client its Core server URL and headers explicitly. Core
server authentication and provider credentials are different. Stop at the first
authentication failure and correct the configuration before another request.

## Mental model

- A `WorkflowSpec` is an in-memory graph of node handlers. A node returns a
  `StepPlan`; it requests side effects through an `Effect` rather than executing
  model/tool work itself.
- `Runtime.start` creates a run, `tick` advances it and `resume` answers its
  current wait using the exact `wait_key`. Read `state.status.value`; a failed
  effect normally returns a failed state with `state.error`.
- `RunState.vars` and effect payloads must be JSON-safe. Store large/binary
  content as artifacts and pass references. Never persist clients, callbacks,
  credentials, Python validator classes or live model handles.
- The run store holds checkpoints; the ledger records attempts and results.
  `get_state` and `get_ledger` read them. Runtime's replay view reconstructs UI
  state; live token deltas are an ephemeral side channel.
- Model/tool calls can cost money or take minutes. Core factories default to
  three LLM attempts and one tool attempt; Runtime backoff starts at one second
  and caps at 30 seconds. Providers can also retry. Use `NoRetryPolicy()` when
  the host should decide whether to retry, and choose explicit generation limits.
- An explicit `_runtime.allowed_tools` list is a run-tree ceiling; `[]` denies
  every tool. Approval cannot grant a tool outside that ceiling.

## Capability map

- Graph execution: `WorkflowSpec`, `StepPlan`, `Runtime.start/tick/resume`; main recipe below.
- Durable human/time/event waits: `ASK_USER`, `WAIT_UNTIL`, `WAIT_EVENT`; inspect stored wait metadata before resuming.
- Storage: `InMemoryRunStore` / `InMemoryLedgerStore`, `JsonFileRunStore` / `JsonlLedgerStore`, SQLite stores; persistence recipe below.
- Model/tools: `create_local_runtime`, `create_remote_runtime`, `create_hybrid_runtime`, `LLM_CALL`, `TOOL_CALLS`; structured and decision recipes below.
- Artifacts/media: `ArtifactStore`, `FileArtifactStore` and JSON artifact refs; generated bytes require a store, documented in the artifacts guide.
- Replay/history: `abstractruntime.replay`, session history and history-bundle export; use the replay guide for rendering clients.
- Scheduling/automation: `create_scheduled_runtime`, durable automation controllers and triggers; the host runs the scheduler/source loops.
- Extensions: WorkflowBundles/VisualFlow compilation, memory and comms integrations, and `abstractruntime-mcp-worker`; use their guides for setup and permission policy.

File stores, artifact stores, snapshots and automation sources can write files.
Core execution may contact providers, load local weights and maintain caches;
comms effects can send messages. The kernel alone performs no model inference.

## Run, inspect and resume a workflow

```python
from abstractruntime import Effect, EffectType, Runtime, StepPlan, WorkflowSpec
from abstractruntime.storage import InMemoryLedgerStore, InMemoryRunStore

def ask(run, ctx):
    return StepPlan(node_id="ask", effect=Effect(
        type=EffectType.ASK_USER, payload={"prompt": "Continue?"},
        result_key="answer"), next_node="done")

def done(run, ctx):
    return StepPlan(node_id="done", complete_output=run.vars.get("answer"))

workflow = WorkflowSpec(workflow_id="approval-demo", entry_node="ask",
                        nodes={"ask": ask, "done": done})
runtime = Runtime(run_store=InMemoryRunStore(), ledger_store=InMemoryLedgerStore())
run_id = runtime.start(workflow=workflow)
state = runtime.tick(workflow=workflow, run_id=run_id)
if state.status.value != "waiting" or state.waiting is None:
    raise RuntimeError(state.error or "Expected a user-input wait")
state = runtime.resume(workflow=workflow, run_id=run_id,
                       wait_key=state.waiting.wait_key, payload={"text": "yes"})
if state.status.value != "completed":
    raise RuntimeError(state.error or f"Run ended as {state.status.value}")
assert state.output == {"text": "yes"}
assert runtime.get_ledger(run_id), "Expected recorded execution"
```

Success is a completed run and a nonempty ledger. For another wait reason, use
the stored wait's contract; a `WAIT_UNTIL` is not a human approval prompt.
Two callers cannot resume one legacy wait: the loser gets `StaleResumeError`.

### Ask an essential or timed clarification question

Add `question: {"importance": "essential"}` to the ASK_USER payload to wait indefinitely
with a fresh `question:<id>` key. For optional clarification, use
`question: {"importance": "clarification", "timeout_s": 120, "fallback": "Compare both options."}`;
only 120–300 seconds is valid. Resume the exact key with `{"response": "the person's words"}`.
Empty responses and approval payloads are refused. At or after the deadline, Runtime returns
`timed_out`, `fallback` and `question.outcome: "expired"`, with no `response`; do not impersonate
the user with the fallback. Explicit pause preserves the deadline and suppresses continuation
until resume. Recognized late replies are retained without answering a newer question.

For public guidance history, supply `display_text` explicitly to `Runtime.steer`; keep original
human words there and any quoted context in the ordinary message argument. An acceptance
receipt means queued, not adopted. Driver-owned entity visits require their participant-checked
visit guidance door, never generic steer. See the API's conversational questions and public
conversation sections for outcome, crash-recovery and single-writer limits.

For approval purpose, read only the optional validated `waiting.details.public_action`:
`text`, `update_id`, `run_id`, positive integer `iteration`, and `call_ids` for that
exact pending batch. Check the run and pending IDs before presenting it. These are
actor-stated public words, not evidence of execution or an approval grant. Keep a
missing explanation explicit; never substitute private reasoning, tool arguments,
or another update. The approval still uses its original wait key and decision. If your host gates before
Core's executor, reuse `approval_public_action(run, original_payload, host_calls, waiting_calls)`
from `abstractruntime.integrations.abstractcore.effect_handlers` before narrowing a delegated
payload, and forward only the returned context (or omit it when `None`).

## Keep the same workflow across restarts

```python
from abstractruntime import Runtime
from abstractruntime.storage import JsonFileRunStore, JsonlLedgerStore

runtime = Runtime(run_store=JsonFileRunStore("./data"),
                  ledger_store=JsonlLedgerStore("./data"))
# Supply the same WorkflowSpec to tick/resume and retain the returned run_id.
```

The directory is created/written locally. Reconstruct the workflow handlers in
the next process; Python callables are not serialized with the checkpoint.

## Request a structured model result

Build a JSON-safe effect for a node handled by an AbstractCore runtime factory:

```python
import json
from abstractruntime import Effect, EffectType

effect = Effect(type=EffectType.LLM_CALL, payload={
    "prompt": "Choose chat or tool.",
    "response_schema_name": "RouteChoice",
    "response_schema": {"type": "object", "properties": {
        "choice": {"type": "string", "enum": ["chat", "tool"]}},
        "required": ["choice"]},
    "structured_output_fallback": False,
    "params": {"max_tokens": 256},
}, result_key="route")
json.dumps(effect.payload)  # request preparation only; no inference
```

Return this effect in a `StepPlan` and wire the workflow to the intended
`create_local_runtime(provider=..., model=...)`, or
`create_remote_runtime(server_base_url=..., model=..., headers=...)`. Handle a
failed state before using `run.vars["route"]["data"]`; valid structured output
is stored there. Local execution creates validators in the inference process;
remote execution sends an OpenAI JSON-schema response format. Do not assume
identical local/remote coercion. These calls do not stream tokens.

## Ask a decision model

A decision is text in, calibrated typed answers out: no text generation, no
artifact. Put the state (the document) in `prompt` and the questions in the
output spec:

```python
effect = Effect(type=EffectType.LLM_CALL, payload={
    "prompt": "Shoes arrived two weeks late and in the wrong size.",
    "output": {"modality": "decision", "model": "mlx/jaredpalmer/kev-4b",
               "questions": {
                   "department": {"type": "choice", "instructions": "Which team should handle this?",
                                  "criteria": ["returns", "billing", "shipping"]},
                   "urgent": "Is the customer asking for urgent help?"}},
}, result_key="triage")
```

For an existing run, the run facade records the decision as a durable child run:

```python
from abstractruntime.integrations.abstractcore import get_abstractcore_run_facade

child = get_abstractcore_run_facade(runtime).decide(
    parent_run_id, state="...", questions={...}, model="mlx/jaredpalmer/kev-4b")
answers = child.output["result"]["answers"]
```

Questions are `choice`, `noul` (a statement's probability of being true) or
`score` objects, or shorthand: a string is a yes/no question, a list is a
choice. `model` may be a `provider/model` handle (`mlx/jaredpalmer/kev-4b`,
`huggingface/ggml-org/Kev-4B-GGUF:Q4_K_M`); omit it to use the `output.decision`
capability default of the client or Core server. The result carries `answers`
(name to typed answer with `confidence` / `probabilities`), `decision` (the
System One body: `model`, `answers`, `usage`, `latency_ms`, `truncated` when
the state was cut), `content` (the answers as JSON) and the decision model's
`provider` / `model`. The VisualFlow `decide` node asks one question (inputs `state`, `question`,
`question_type` = `choice` | `noul` | `score`, `options` or `levels`, `provider`,
`model`, `truncate`) and fills that type's pins (`answer`; `choice`/`confidence`/
`probabilities`, `noul`/`verdict`, or `score`/`level`); a wired `questions`
object asks several at once and fills `answers`. It lowers to the same effect;
remote runtimes post `/v1/decisions` on the Core server. Threshold `confidence` or the probabilities before acting;
the model only scores the options you give it.

## Rules and sharp edges

Inspect recorded state before repeating a model or side-effectful tool call;
starting a fresh run can repeat paid inference or external actions. An optional
structured repair path can issue another model request; the recipe disables it.
Keep provider/API credentials outside vars and ledger data.

Persist schemas as data, not `response_model` classes. A schema and an explicit
conflicting model/format are a deterministic refusal. Runtime's best-effort
local schema conversion supports nested properties, arrays, enums and defaults,
but does not implement every JSON Schema keyword.

An optional Core HTTP listener is a separate convenience surface. The Runtime
`server_facade.start_core_server` lifecycle helper starts Core's authenticated
listener explicitly; native execution does not require it. Stopping HTTP does
not unload model resources. Core controls resident weights and rejects unsafe
duplicate loading configurations; wrappers and separate KV contexts are not
the same as duplicate weights.

## When things fail

- **Import/version mismatch:** verify in the same Python interpreter, then reinstall the matching checkout/profile.
- **Waiting indefinitely:** inspect `state.waiting.reason` and its key; answer a user/tool wait or arrange the event/scheduler it requests.
- **`StaleResumeError`:** reload state; another caller already consumed the wait. Do not replay the approval blindly.
- **Structured request refused:** use an object schema with nonempty properties and identifier-style names; remove conflicting model/format inputs. Fix deterministic input errors instead of retrying.
- **Remote failure:** check the Core URL, credentials and recorded error; native Runtime calls do not use Gateway credentials as Core server tokens.
